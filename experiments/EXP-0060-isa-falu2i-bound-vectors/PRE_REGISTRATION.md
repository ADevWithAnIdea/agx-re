# EXP-0060 pre-registration — bound FALU2I property vectors

This is the separately numbered successor to EXP-0059. Frozen before any
EXP-0060 analysis run. Scope is repository-authored ISA codec data only; no
Apple binary, Apple-compiled output, native probe, unknown BO, A18, or M4
hardware claim is made.

## Question and bounded claim

Can the already HW-validated `falu2i` immediate form gain an auditable central
property-vector increment for its explicit semantic sub-schema? The answer may
only be that the current table codec round-trips the listed finite domain. It
does not establish hardware execution of generated bytes or compiler readiness
for fields excluded below.

Semantic fields: `dst`, `srcA_size`, `srcA_reg`, `opsel`, `imm_flag`,
`imm_mant`, `imm_exp`, `imm_sign`. Excluded non-semantic modifier fields:
`opflags`, `ctrl_lo`, `mods`; they are fixed zero and never promoted.

Domain: dst `{0,1,7,15}`; srcA_size `{0,1}`; srcA_reg `{0,1,31,63,95}`;
opsel `{4,5}`; imm_mant `{0,1,7}`; imm_exp `{8,11,15}`; imm_sign `{0,1}`;
imm_flag `1`. This is exactly 1,440 vectors. Every one must produce a unique
six-byte encoding, decode unambiguously as `falu2i`, preserve semantic fields,
preserve excluded zero fields, and byte-round-trip. Any failure is a stop.

## Capture/provenance gate

Before invoking the central round-trip suite or generating a vector, the
analyzer creates exactly `raw/run01/00_inputs.json` containing the current Git
revision and SHA-256 for this preregistration, analyzer, `isadb.py`,
`roundtrip_test.py`, and `db.json`. It then writes exactly one `result.json`.
The tree must contain no extras, symlinks, or special files. Verification checks
the raw source hashes against Git blobs at that captured revision and requires
the revision be an ancestor of HEAD. The raw result is invalid if this binding
is absent or mismatched.

Clean-room provenance: STRUCTURAL / OWN-SHADER-derived repository data. Apple
binary introspection: NONE.
