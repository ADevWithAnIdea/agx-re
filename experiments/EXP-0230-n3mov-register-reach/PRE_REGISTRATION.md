# EXP-0230 pre-registration — `n3_mov` full source-register reach

Frozen before the first dispatch. Repository base: `180608dd847b20939fcca1d80fba29be93ec8b78`.

## Question

When all 96 architectural GPRs contain independently recognizable values, what exact source set
does the four-byte `n3_mov` half-register move address through byte `+1`? In particular, does its
top source bit select r64–r95, alias r0–r31/r0–r63, or select an invalid region; and what happens
at the architectural boundary r95/r96?

EXP-0174 proved the instruction and both half selectors, but its carrier made only r0–r15
host-known. Its reported period-64 result therefore could not distinguish an ignored source bit
from a source register that the carrier never initialized. EXP-0224 subsequently relied on the
stronger, unproved claim that the move stages arbitrary r0–r63 values. This experiment supplies
the missing live-register carrier.

## Frozen hypotheses

For encoded source `S = byte1 >> 1`:

- **H96 (primary):** S=0..95 reads the corresponding distinct architectural GPR; S=96..127 is
  outside the 96-GPR file and reads zero without aliasing.
- **H64:** source bit 6 is ignored and every S aliases `S mod 64`.
- **H64Z:** S=0..63 is direct and every S=64..127 reads zero.
- **H96W:** S=0..95 is direct and S=96..127 wraps modulo 96.
- **HF:** one or more values at or above a boundary fault or hang rather than returning a value.

The experiment scores every successful case against all four value models. A command-buffer fault
or hang is a fifth, separately recorded outcome. H96 is refuted by any clean S=64..95 case that
returns its lower alias/zero instead of the independently seeded high register, or by any S>=96
case that returns a nonzero alias.

## Variables and coverage

- Source descriptor: every byte value 0..255, equivalently S=0..127 × source half low/high.
- Destination half: fixed low (`hd=0`). EXP-0174 already closed the independent destination-half
  selector; fixing it here avoids the database's known `n3_mov`/`mov_zext16` descriptor overlap
  and leaves source reach as the only semantic variable.
- Destination: r2 except when S=2, where r3 is used; source and destination are not aliased in the
  main reach arm.
- Register/readback plan: two complete plans, with r14 or r15 reserved as the zero index register.
  Every source is therefore initialized in at least one plan, including r14/r15.
- Target: Apple A18 Pro / G17P at `192.168.170.254`, compute stage, one thread.

The 512 main cases are run twice in opposite order. Two wrong-oracle controls deliberately predict
the value of r2 when the emitted instruction reads r1; they must fail the complete-state oracle.

## Carrier and independent state

The carrier is our own `carrier230.metal`, copied from our own EXP-0221 authored carrier only to
provide buffer bindings and a sufficiently long `_agc.main` region. The whole region is replaced by
generated bytes, so no compiler-emitted instruction is executed or copied.

For each plan, every r0..r95 except the reserved index register is loaded from authored
`imem[900+R] = 0x5A17C0DE XOR (R * 0x01010101)`. These codewords have independently recognizable
low and high halves. Sixty-four generated `mov_imm(index,0)` instructions separate the load wave
from observation. A pre-move store of the selected valid source is a seed/readiness witness; a
case whose witness is wrong cannot advance move semantics.

The readback contains the destination before and after the move, the selected source before and
after where it is in-range, its modulo-64 comparison register, and all r0..r15 after the move.
Stores use EXP-0221's generated even-half `device_store.extmode=2*R` path, which directly read
r0..r95 on G17P. Independent pre- and post-body sentinels distinguish execution failure from a
silent zero or no write. Buffers begin poisoned.

## Five gates

- **A — geometry:** preserve caller fields, generated instruction bytes, actual dispatched bytes,
  independent field decode, offsets, complete program hash, and distinct byte counts. Every byte1
  value 0..255 must appear exactly.
- **B — detection:** the normal r1→r2 cases must change the selected destination half; both
  wrong-oracle controls must fail. Source seed witnesses and sentinels must pass.
- **C — semantics:** successful observations are compared to H96/H64/H64Z/H96W, not merely to a
  baseline. A model can win only if it predicts every decidable valid record in both runs.
- **D — generation:** all `n3_mov`, load, store, marker, and stop fields are constructed from
  documented rules. `COPIED=0` and `CARRIER=0` are mandatory.
- **E — target/reproduction:** two quiet G17P runs in canonical and reverse order, identical
  program hashes and actual-byte ledgers, no foreign runner, and no unexplained recovery delta.

## Finite-boundary rule and safety

The complete encodable source namespace is exercised. r95 is the maximum proposed valid register,
r96 is the first proposed invalid register, and r97..r127 distinguish fault, zero, wrap, alias, and
other behavior. Any fault/hang is retained and retried in isolation before a finite-boundary claim.

Every dispatch has a 20-second watchdog; raw JSONL is append-only and line-flushed. If the device
becomes unresponsive, immediately stop, preserve the last record, perform no recovery or reboot,
and report the goal blocked, per the user's plan-level stop rule.
