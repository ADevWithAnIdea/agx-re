# EXP-0123 -- M4 rasterization rules and hard resource limits (P1.8 / DRV-RASTER-01)

## Question

`APPLE9_RE_IMPLEMENTATION_GAPS.md` DRV-RASTER-01 and `docs/P0-P1-CLOSURE.md` row
P1.8 require characterizing, on hardware, everything the numerical-side experiments
(EXP-0047, EXP-0074, EXP-0102, EXP-0103) do not cover: line/point rasterization
rules, polygon (fill) modes, depth clip vs. clamp, conservative rasterization,
coverage/early-late depth-stencil interaction beyond EXP-0091, and every advertised
finite resource limit the row names -- each one CONSTRUCTED on real hardware
(minimum, maximum, first-invalid, holes), not quoted from a feature table.

## Hypothesis

See `PRE_REGISTRATION.md` -- a per-family table of exact predicted values/behaviors,
derived from real exploratory hardware probing performed before the matrix was
frozen, re-confirmed by two independent, byte-identical, gated captures.

## Method

`harness/casematrix.py` (98 cases, 18 families) is the single frozen source of
truth. `harness/genkernels.py` deterministically regenerates MSL per case.
`harness/rasterprobe.m` (render/multiattach/texcreate/bufferindex/bytesconst/
bufferalign/texturebind) and `harness/computeprobe.m` (compute dispatch) are the
two authored, JSON-in/JSON-out Metal probes -- every risky operation is wrapped in
`@try/@catch` where Metal raises a catchable exception, and `run.py` classifies an
uncatchable `abort()`/`SIGSEGV`/GPU-hang as its own first-class outcome rather than
treating it as harness failure. `harness/run.py` drives one FRESH SUBPROCESS per
case with a 25 s hard timeout, appending `fflush`+`fsync`'d JSONL records after
every case. `harness/verify.py` implements the five standing gates.

## Commands (exact reproduction)

```sh
# NON-RECORDED smoke gate (already run once as `pilot1`; do not repeat unless the
# harness changes -- a partial/defective capture is retained, never overwritten,
# per SUBAGENT_BRIEF.md):
python3 harness/run.py --run pilotN --out work/pilot_run

python3 harness/verify.py --selftest
python3 harness/verify.py --seqtest

# Official capture (two independent runs into raw/):
python3 harness/verify.py --preflight
python3 harness/run.py --run m4_20260828_run01 --out raw/m4_20260828_run01
python3 harness/verify.py --between-runs
python3 harness/run.py --run m4_20260828_run02 --out raw/m4_20260828_run02
python3 harness/verify.py --captured m4_20260828_run01 m4_20260828_run02

# Derived report (used to build the RESULTS.md limit table):
python3 analysis/report.py raw/m4_20260828_run01
```

Rebuilding the probes (already built; `work/bin/` is gitignored-equivalent scratch,
rebuild if missing):

```sh
clang -fobjc-arc -framework Metal -framework Foundation -O1 -o work/bin/rasterprobe harness/rasterprobe.m
clang -fobjc-arc -framework Metal -framework Foundation -O1 -o work/bin/computeprobe harness/computeprobe.m
```
