# EXP-0057 pre-registration — M4 public scratch-pressure envelope

Date frozen: 2026-08-19 (America/Los_Angeles)

Target: local Apple M4 / G16G-class GPU only. A18 Pro / G17P is not available
for this batch and no result transfers to it.

Gap: `AGX_RE_INFORMATION_GAPS.md` P0.1. EXP-0041 established that ordinary
public-Metal CS/VS/FS workloads declaring 208--576 bytes of per-thread scratch
can execute on M4, while a narrowly allowlisted boundary trace exposed neither
a helper record nor a separately mapped scratch allocation. It deliberately did
not establish the pressure/failure envelope, concurrent allocation behavior, or
reset semantics that a userspace scratch implementation would need.

This experiment asks the smallest next question that remains observable without
opening that boundary: for a fixed, completely authored compute workload, which
compiler-declared per-thread scratch demands complete under two execution-width
shapes, and what public completion/error behavior bounds the first failure?

It cannot locate, identify, synthesize, or validate a Linux helper program,
helper `binary`/`cfg`/`data`, scratch BO geometry, a doorbell, a special register,
or a tagged pointer. It cannot close P0.1.

## Frozen clean-room boundary

This is a `HW-PROBE + OWN-SHADER source + PUBLIC API` experiment.

The only inputs that may be opened or retained are complete MSL sources authored
for this experiment; the experiment's own public Metal compilation diagnostics;
public pipeline properties; the experiment's own scalar metadata emitted by its
own parser from its own pipeline archive; public command-buffer status/error
objects; and the experiment's own output buffer/readback.

No IOKit interposer, private API, BO mapping, BO dump, command/state/code-buffer
capture, resource-map trace, pointer following, memory mutation/replay, system
cache access, or executable inspection is in scope. No Apple binary, framework,
driver, compiler implementation, kernel, firmware, Apple auxiliary/helper
program, or non-authored compiled code may be disassembled, scanned, opened as
data, debugged, or otherwise introspected. The MSL compiler is used only as a
black box through public Metal APIs. No compiled shader bytes, including bytes
from our own shaders, are retained or inspected in this experiment.

Each recorded source is generated by and retained with the authored generator.
Its complete source text and SHA-256 are retained before compilation. An archive
parser may extract only the documented scratch-size and GPR metadata fields
already established for this project's **own** pipeline metadata; it must reject
and retain a stop if the archive cannot be shown to belong to the just-compiled
complete authored source. It must not enumerate, read, or retain other archive
members or any code bytes.

## Driver decision and hypotheses

The driver decision is narrow: whether the known ordinary-Metal spill evidence
can provide a safe finite pressure bound or allocation-failure observation for a
future userspace scratch helper. It must never be treated as authority to invent
the helper ABI.

### H1 — declared scratch remains executable through a bounded ladder

For each pressure level whose own metadata reports nonzero scratch, the checksum
is exact and command-buffer completion is successful for both execution shapes.
This supports only a lower bound: M4's ordinary private-scratch service accepts
that declared byte count for this workload and shape.

H1 is falsified at a level/shape by compile rejection, nonzero command-buffer
error, timeout, device removal/reset, a nonzero scratch field with incorrect
authored readback, or a mismatch between independently repeated exact cases.

### H2 — execution shape exposes an ordinary-Metal pressure boundary

At equal total thread count, changing only threads-per-threadgroup from 32 to
256 either preserves success or yields a reproducible public failure/status
boundary. A reproducible boundary is a public service-limit observation, not a
per-core block count, helper allocator limit, or Linux limit.

H2 is falsified for the tested ladder if every qualifying nonzero-scratch level
has exact successful readback and matching public status for both shapes. An
inconsistent one-off failure is a bounded stop, not a limit claim.

### H3 — larger declared scratch has a monotone public failure frontier

If failure first appears while increasing only the generated pressure level, all
smaller qualifying levels complete and the first failing level reproduces in a
fresh process. This is falsified by nonmonotone or irreproducible outcomes. In
either case, the experiment records observations only and does not extrapolate.

## Frozen authored workload

`kernels/generate.py` (to be authored only after this registration is committed)
will emit one complete MSL compute source for each named level. Each source uses
an explicitly indexed private `uint` array, a data-dependent recurrence fed by
an authored input buffer, and a full reduction into an authored output buffer.
The retained output vector, not a compiler assumption, verifies that every
declared array element affected the final value. The generated source must
contain no imported source, embedded library, function constant, indirect call,
or non-authored code.

The predeclared source levels are intentionally modest and finite:

| case | requested private array bytes | purpose |
| --- | ---: | --- |
| `baseline` | 0 | known low-pressure control |
| `p576` | 576 | EXP-0041 upper successful point control |
| `p1024` | 1024 | first extension |
| `p2048` | 2048 | doubling step |
| `p4096` | 4096 | doubling step |
| `p8192` | 8192 | doubling step |
| `p16384` | 16384 | capped final step |

The requested private-array size is not a claimed compiler scratch size. The
pipeline's own parsed metadata determines whether a case qualifies as a
nonzero-scratch case. A zero/absent/ambiguous field is retained as a compiler
outcome and receives no scratch-service interpretation.

Every level runs under exactly two public execution shapes, each with exactly
32,768 total threads and no other work in flight:

| shape | threads per threadgroup | threadgroups | total threads |
| --- | ---: | ---: | ---: |
| `tg32` | 32 | 1024 | 32768 |
| `tg256` | 256 | 128 | 32768 |

The output buffer has one 32-bit word per thread and a 64-byte prefix/suffix
guard filled with asymmetric authored values. The input allocation, source,
pipeline options, output allocation, dispatch count, device, queue, command
buffer, and completion wait are fresh for every trial process. The only intended
factor change within a pair is the named source level or execution shape.

There are 14 cases per top-level run. Two append-only top-level runs are
mandatory: 28 fresh GPU processes total. The second run must be initiated only
after all retained first-run artifacts have passed local completeness/hash checks.

## Safety and stop rules

- Compilation has a 20-second hard timeout; GPU completion has a 15-second hard
  timeout per fresh process. A parent watchdog kills only its own child process.
- At most one command buffer is committed per process and no concurrent queues,
  events, shared memory, or IOKit services are used.
- The maximum requested array is 16 KiB/thread and the maximum submitted
  aggregate nominal request is 512 MiB (16 KiB x 32,768). The harness must
  reject any generated source or dispatch exceeding those caps.
- A compile rejection is recorded and does not itself stop lower or independent
  cases. A timeout, device-loss/reset indication, or GPU fault stops the current
  top-level ladder immediately; no higher pressure case, retry, or automated
  recovery is attempted. The raw failure record and parent watchdog status are
  retained append-only.
- A fresh-process repeat of a first public failure is permitted only if the
  failure was a normal completed command buffer with a documented status/error,
  not a timeout, fault, reset, or device loss. It runs once, then the ladder
  stops regardless of result.
- If the system does not recover normally after a fault/timeout, stop the whole
  experiment and leave recovery to the operator. No reboot is automated.

## Acceptance and analysis rules

Before interpreting a successful case, the analyzer must verify: exact case
matrix; regular, non-symlink files; one complete source and source hash per
case; public target identity; a source-to-pipeline identity record; a finite
metadata record; full 32,768-word output; exact prefix/suffix guards; exact
expected output word for every thread; explicit command-buffer status; and no
unexpected files. A missing/extra/short artifact, compiler diagnostic mismatch,
or non-authored provenance failure is a bounded stop for that case.

For each level, the report must separately state:

1. requested source-array bytes;
2. observed own-pipeline scratch and GPR metadata, or parser/compile stop;
3. public compile and completion status for `tg32` and `tg256`;
4. exact readback/guard result where completion occurred;
5. first failure and reproduction status, if any; and
6. the explicitly unestablished helper/scratch-ABI facts.

No byte size is called a hardware allocation, block size/count, per-core limit,
or helper limit. Successful ordinary Metal execution is a lower bound only for
this M4/compiler/OS/workload. A failed compile or execution is not a Linux UAPI
constraint without an independent Linux-compatible proof.
