## Evidence that triggered this amendment

The target r95 and comparison r1 pre-witnesses were both the intended `0x0548bd81`, but the

files have hashes:

This refutes promotion of the original primary model as written, but does not by itself distinguish
a high-register selector effect from a condition-recipe error.

## Discovered protocol error

The pre-registration calls the test integer equality, but `emit_isel()` requested `cc=0`.
EXP-0223's proven table assigns `cmp_mode=0x06, cc=7` to integer equality and reserves
`cmp_mode=0x06, cc=0` for floating equality.  The codewords used by this experiment are finite
non-NaN floats, so this mismatch does not explain away the observation, but it tests the wrong
operation and must be corrected before reach claims are made.

All subsequent EXP-0234 dispatches use `cmp_mode=0x06, cc=7`.  The original pilot is retained only
as diagnostic evidence and can never be promoted.

## Frozen staged discovery

Before either full formal sweep, run an amended calibration/discovery matrix through an exact-name
filter added to the generic harness:

- low controls r0 and r23 for each source role;
- boundary candidates r24, r31, r32, r47, r48, r63, r64, r79, r80, and r95 for each source role;
- one run in ascending name order and one in reverse name order;
- preserve complete state and the exact/modulo candidate channels already generated by the harness;
- stop immediately on any hang or an unresponsive device.

The sparse matrix is discovery evidence.  Its result determines a second, separately frozen
confirmation amendment: dense direct ranges, explicit alias-discrimination probes where equality
alone is ambiguous, and first-outside behavior.  No sparse result may be silently converted into a
compiler claim.

The original formal and boundary run IDs remain unused.  They must not be dispatched until the
corrected confirmation model is frozen.
