# EXP-0222 — canonical low-register `iadd2` recipe and lifecycle

Pre-registration time: 2026-08-31, before this experiment's first dispatch and before compiling
or inspecting any fresh Metal integer-add oracle.  The experiment number skips remotely-present
`EXP-0221`; no `EXP-0221` artifact is read or modified.

Target: Apple A18 Pro / G17P at `192.168.170.254`, macOS 26.6, Metal family Apple9.

Clean-room class: OWN-SHADER carrier + HW-PROBE.  The carrier source is our own existing
`EXP-0220` compute carrier.  Every instruction byte executed in the generated program is assembled
from documented rules.  A fresh Metal compile is used only to create the lawful carrier archive
and pipeline container; its `_agc.main` instruction bytes are replaced and are not inspected as an
integer-op oracle.

## 1. Compiler question

Can a compiler generate arbitrary low-register 32-bit integer add/subtract programs with no
compiler-emitted donor instruction, including register reuse and the lifecycle contexts a normal
SSA-destruction/register-allocation pass produces?

This experiment does not claim to close all integer ALU, comparisons or selects.  It closes the
first primitive in that programme: a canonical two-register `iadd2`/`isub2` recipe.

## 2. Frozen primary model H1

For `A`, `B`, and `D` in `r0..r14` (r15 is reserved by the harness as the store index), emit:

```text
addsub       = 1 for D = A + B; 0 for D = A - B
lenbit       = 1
srcB_reg_hi  = 0
b2_bit0      = 0
store_en     = 1
b2_fmt       = 0x15
dst          = (D << 1) | 1
opmode       = 2
srcB_imm     = B << 2
srcB_imm_hi  = 0
srcB_ext     = A << 2
srcA         = 0xA8
opc_tail     = 0x17
opc_tail2    = 0x05
```

Predicted arithmetic is modulo 2^32.  H1 is derived from the G17P-direct correction in EXP-0154:
`srcB_ext >> 2` selects the first GPR and `srcB_imm >> 2` selects the second.  Fixed values are the
already-generated natural register-form values, chosen as a canonical point rather than copied as
a byte token.

Refuters:

- a result fits `r0 + rB` rather than `rA + rB`;
- either source is pair/half indexed rather than `field >> 2`;
- destination placement is not `(D << 1) | 1`;
- any complete-state mismatch, silent no-write, collateral register change, fault or hang;
- the same generated bytes cease to predict the same result under register reuse or a different
  instruction order.

## 3. Alternatives frozen before failure

These alternatives may be dispatched only if H1 fails.  They count as distinct independent
attempts before any fresh Metal integer instruction may be inspected.

- H2: operand packing is `(reg << 1) | is32`; use `srcB_ext = (A << 1) | 1` and
  `srcB_imm = (B << 1) | 1`.
- H3: EXP-0154 identified the two register fields but their roles were reversed; keep H1's packing
  and swap the `A` and `B` selectors.  Subtraction with asymmetric inputs distinguishes H1/H3.

If all three fail, retain all failures and only then compile a new authored MSL add/sub carrier and
inspect the machine code emitted from that source.  No Apple binary or Apple-authored shader is
ever inspected.

## 4. Lifecycle hypotheses

With H1's canonical fixed fields:

1. both sources remain readable after the instruction;
2. the destination is published for the immediately following ALU instruction;
3. `D == A`, `D == B`, and later redefinition of `A`, `B`, or `D` behave like ordinary destructive
   SSA destruction, using the values read before the write;
4. a load-produced source is accepted by the same recipe after one independent instruction; an
   immediately adjacent load is measured separately and not assumed safe;
5. chaining up to 64 generated adds/subtracts with physical-register reuse introduces no hidden
   finite pending-slot resource.

Every arm dumps all r0..r23.  A source-release or collateral write therefore appears in the host
comparison even if the final arithmetic result is correct.

## 5. Case matrix

- `ctl`: generated prologue + dump, and a known arithmetic falsifier.
- `cross`: all ordered `(A,B,D)` points from a covering set over r0..r14, including aliases,
  extremes, and asymmetric subtraction.
- `lifecycle`: immediate destination use, source rereads, source/destination aliases, overwrite,
  and distances 0/1/2.
- `provenance`: operands produced by `mov_imm`, `n3_mov`, prior `iadd2`, and `device_load`.
- `dag`: at least 100 deterministic random programs, 2..64 integer nodes, physical-register reuse,
  two instruction orders, and an independent host interpreter using modulo-2^32 arithmetic.
- `field`: after the canonical recipe passes, separately sweep every remaining bit/field with
  lifecycle and provenance contexts.  These cases advance capability mapping, not the canonical
  recipe gate.

Initial discovery may use a small `work/pilot/` subset.  Gated promotion requires the full frozen
matrix in forward and reversed or shuffled order.

## 6. Five gates

- Gate A: caller fields, assembled bytes, bytes reread from the dispatched archive, independently
  decoded fields, instruction offsets, and program SHA-256 agree.
- Gate B: poisoned outputs, independent sentinel, complete r0..r23 dump, two disjoint register
  plans, and an arithmetic falsifier that must change the payload.
- Gate C: every case is predicted before dispatch by a host modulo-2^32 register interpreter.
- Gate D: all program instruction fields are `RULE` or a separately cited accepted canonical
  value; `COPIED == 0` and `CARRIER == 0`.
- Gate E: two measured-quiet G17P captures in different case orders, byte-identical per case, with
  no foreign runner, victim cascade, or unclassified measurement failure.

## 7. Safety and stopping

Each dispatch has a 20-second timeout.  Raw output is append-only and flushed per case.  Stop the
arm after 4 hangs or 8 contained faults not explicitly predicted.  Do not use `macvdmtool` unless
SSH itself becomes unresponsive; tell the user before using it unless the session is explicitly
unattended.

## 8. What success and failure mean

Success closes a canonical low-register 32-bit `iadd2`/`isub2` recipe and its tested lifecycle
envelope.  It does not close immediate mode, 16/64-bit forms, arbitrary r15/r16+ destinations,
comparison/select, or every capability bit.

Failure is retained per model and narrows the operand/lifecycle hypotheses.  A carrier with a failed
positive control is `carrier-undecidable`, never evidence that a bit is unused.
