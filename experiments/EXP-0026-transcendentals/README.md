# EXP-0026: transcendental / special-function lowering (rcp, rsqrt, sqrt, sin, cos, exp, log, pow, div)

- **Date:** 2026-07-07
- **Clean-room category:** OWN-SHADER + HW-PROBE (+ PUBLIC for the applegpu *shape*)
- **Phase / question:** acceptance-gate gap **G-2 (CRITICAL)** — a compiler must know exactly
  how to lower `1/x`, `rsqrt`, `sqrt`, `sin`, `cos`, `exp`, `log`, `pow`, `a/b`, which are all
  multi-instruction on G17P. Follow-up to EXP-0013 (which found exp2/log2/round are single
  `0x2f/0xaf` ops and noted frcp/frsqrt/fsqrt are multi-instruction Newton-Raphson seeded by a
  `0x29` estimate).
- **Device state:** Apple A18 Pro / G17P, SoC T8140, macOS 26.6 (25G5043d), Metal 4 / Apple9.

## Hypothesis
The transcendentals lower to a small hardware **special-function unit** (SFU) plus, for
correctly-rounded results, a software Newton-Raphson refinement seeded by a low-precision
**estimate** op. Specifically: (a) a `0x29` estimate op provides ~a-few-bit reciprocal/rsqrt/sqrt
seeds; (b) exp/log/pow/div compose the SFU primitives (exp2, log2, rcp); (c) sin/cos are range
reduction + polynomial.

## Method (clean-room: OWN-SHADER)
We write our own MSL kernels (`kernels/*.metal`, generated by `gen_kernels.py`) for each function
in three forms — default (fast-math), `--no-fast-math` (precise), and the `metal::fast::` /
`metal::precise::` namespaces — compile them **on the device** with our `shdump`, extract the
`_agc.main` bytes with our `agxparse.py`, and disassemble **our own** compiled bytes with our
`agx-isa` DB (`dump_seq.py`). We then splice our own bytes and run them on the real GPU
(`agxrun_persist` / `persistrun.py`) to (1) read the **raw estimate** before refinement and measure
its precision, and (2) validate the accuracy (ULP) of the full lowered sequences. No Apple binary
is ever disassembled or introspected; per CLAUDE.md rule 5 we document instruction *encodings,
semantics and precision* (hardware facts), not the compiler's exact scheduled NR instruction list.

## Procedure
```sh
# on device, ~/cleanroom_work/exp0026/  (tools staged from tools/{shdump,agxtest,agx-isa})
python3 gen_kernels.py                              # emit our MSL kernels
python3 dump_seq.py --fast <kernels...>             # compile+extract+disassemble (fast-math)
python3 dump_seq.py <kernels...>                    #   ... precise (--no-fast-math)
python3 est_precision.py rcp rsqrt sqrt             # read raw 0x29 estimate -> mantissa bits
python3 estimate_probe.py rcp                       # per-register dump of the precise rcp store
python3 validate.py <kernels...>                    # HW ULP validation, fast + precise
```
Raw logs: `raw/disasm_fast.txt`, `raw/disasm_precise.txt`, `raw/estimate_precision.txt`,
`raw/estimate_regsweep.txt`, `raw/accuracy.txt`.

## Raw results
See `RESULTS.md` for the full analysis. Headlines:
- **Estimate op** = byte0 `0x29`, 6 bytes, `29 81 25 <subop> 00 c2`; subop byte+3 = `0x09` rcp /
  `0x0b` rsqrt / `0x0d` sqrt. HW-measured precision **~7.5–8.0 good mantissa bits**.
- **SFU op** = byte0 `0x2f/0xaf`, 10 bytes (the EXP-0013 `fspecial` group). One op computes
  rcp/rsqrt/exp2 (`0xaf`) | round/sqrt/log2 (`0x2f`), function = byte+1.
- exp/exp10 = `exp2(x·k)`; log/log10 = `log2(x)·k`; **pow(a,b) = exp2(b·log2(a))**;
  **a/b = a·rcp(b)**; sin/cos/tan = range-reduction + polynomial (fma chains + a `0x2b` reduce op),
  tan = sin·rcp(cos).
