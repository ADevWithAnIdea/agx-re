# EXP-0097 — M4 varying/UVS export capacity (GLIO-A01) + pre-raster special-output ABI (GLPRE-A03)

**Question.** (1) What is the exact, hardware-usable capacity of the vertex-output ("varying")
scalar namespace and the clip/cull-distance namespace, and what happens at the first value beyond
each limit (`GLIO-A01`)? (2) What does Apple9/Metal hardware actually do at the public-Metal
boundary for NaN/Inf/signed-zero clip-space positions, point sizes (zero/negative/huge), an
out-of-range render-target-array-index or viewport-array-index, and the provoking-vertex convention
(`GLPRE-A03`)?

**Why it matters.** Both items close rows in `work/ADDENDUM-TRIAGE-20260828.md` "Bundle G" and
`APPLE9_RE_OPENGL_TEXTURE_ADDENDUM.md:31-49,360-386`, deepening `DRV-ABI-01`. `EXP-G1a` located the
varying-count command-stream field (`0x58000+0x2c = 4 + 4·nvary`) but validated it only for
`nvary` 0..8 (36 total scalars) — far short of the real ceiling. GLPRE-A03's six sub-questions
(NaN/Inf/signed-zero position, point size, OOB layer, OOB viewport, provoking vertex) had no prior
experiment.

**Method.** Pure `OWN-SHADER` public-Metal-API probing — no assembler, no splicing (per dispatch:
"no assembler needed for the capacity sweep"). `harness/genkernels.py` generates parametrized MSL
from string templates; `harness/capacityprobe.m` compiles + attempts render-pipeline creation only
(the GLIO-A01 capacity sweeps — distinguishes MSL-frontend rejection from
`newRenderPipelineStateWithDescriptor:`-level rejection); `harness/renderprobe.m` compiles, builds
a pipeline, draws, and reads pixels back in 4 modes (plain 2D target, point-topology footprint,
`texture2d_array` layer readback, multi-viewport tiled readback) for GLPRE-A03 and for a small
`vary_render_confirm` family that goes past pipeline-creation to a real checksum-verified draw at
the capacity boundary (silent-aliasing check). 140 frozen cases across 11 families
(`harness/casematrix.py`); two full official capture runs, byte-identical on every gated field.

**Clean-room category:** OWN-SHADER. Every `.metal` source is authored-template-generated by us;
only the public Metal runtime API and its public error/pixel-readback surface are touched. No
native AGX instruction is decoded or spliced anywhere in this experiment — see `RESULTS.md` §0 for
the explicit statement that the concurrently-reported `db.json` ALU-retention-flag decoding bug
(`work/COMPILER-EXPLAINER-INTERACTION-20260828.md`) does not apply here.

