# EXP-0227 — pre-registration (frozen before first dispatch)

Target: Apple A18 Pro / G17P (`192.168.170.254`). Clean-room class:
OWN-SHADER carrier + generated instructions + HW-PROBE. No fresh Metal output
for the low-nibble-9 operation under test may be inspected until at least two
materially different generated hypotheses fail.

This is a **pilot for one Step 1 grammar edge**, not an attempt to close Step 1
and not an arithmetic-semantics experiment.

## Question and hypothesis

Does the generated prefix `09 01 20 05` consume exactly four bytes on G17P?

**H1:** in the low-nibble-9 group, `byte+2 & 7` in `{0,1}` selects a four-byte
form before any later extension field is consulted. Therefore `09 01 20 05`
ends after byte 3, and the `mov_imm` beginning at relative offset 4 executes.

The narrower alternative is that the current corpus tokenizer manufactured a
boundary and hardware consumes 6, 8, 10, 12, or some other length. Arithmetic
output from the candidate is deliberately not predicted.

## Generated byte geometry

The candidate is assembled as `falu_compact4` from these independently stated
fields, not copied from a compiler token:

```text
dst=0, src=0x01, opsel=byte2&7, opmode=byte2>>3, operand=0x05
```

After it, generated two-byte `mov_imm` markers start at offsets:

```text
+4   first causal marker (case-specific register and immediate)
+6   r3  = 91
+8   r4  = 92
+10  r5  = 93
+12  r11 = 94       # post-candidate resynchronization control
```

For a consumed length L in `{4,6,8,10,12}`, a marker executes exactly when its
offset is at least L. This predicts five distinct complete-register signatures.
The `+12` marker must execute under every listed model, separating a bounded
length result from downstream desynchronization.

the frozen `out=0, mem=1, imem=2` map does not reproduce.

## Gates and evidence axes

- **Actual bytes:** the archive is reread after replacement; the exact candidate
  bytes and following ten bytes are recorded per case.
- **Detection:** complete r0..r23 state, all three buffers, poison, and an
  independent sentinel are checked. The wrong-host-model case must be rejected.
- **Independent prediction:** expected marker signatures are computed from
  byte offsets and candidate length, not from candidate arithmetic semantics or
  the shared tokenizer.
- **Generated recipe:** `COPIED=0` and `CARRIER=0`; Gate A independently extracts
  every requested field from the actual generated bytes.
- **Target:** only G17P hardware can answer H1. Corpus tokenization remains
  structural evidence and is not promoted by this experiment.
- **Reproducibility:** this pilot is one disclosed bounded run. It cannot close
  the rule; two quiet formal runs in different orders require an amendment.

Geometry may advance while arithmetic semantics, source lifecycle, and recipe
generality remain open. No one-dimensional "instruction solved" label follows
from this result.

## Refuters and inconclusive outcomes

- Any H1 marker signature other than the unique length-4 signature refutes H1
  for that generated point, assuming the post marker and sentinel succeed.
- If the post marker or sentinel fails, or the command buffer faults/hangs, the
  case is **inconclusive**, not evidence for a longer length.
- If r0 appears to match by coincidence but the changed-immediate case does not
  track it, H1 is not accepted.
- If the changed-destination case does not write r6, H1 is not accepted.
- If the wrong host model is accepted, the measurement has no detection power.
- Gate A disagreement, a donor field, stale remote hash, slot-map mismatch, or
  foreign GPU activity invalidates the pilot.

Stop after more than one hang. Do not recover/reboot the Neo while the user is
present without asking. Raw records are append-only and run IDs are never reused.
