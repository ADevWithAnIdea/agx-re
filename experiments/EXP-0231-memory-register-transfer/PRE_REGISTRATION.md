# EXP-0231 pre-registration — device-memory transfer between GPR tiers

Frozen before the first hardware dispatch. Repository base: `1378b393`.

## Question

Can a fully generated Apple9 sequence transfer an arbitrary 32-bit value from one architectural
GPR to a different architectural GPR by storing it to bound device memory and loading it back?
Does the sequence work in every direction among the compact r0..r15, middle r16..r63, and upper
r64..r95 tiers, and what instruction separation is required between the store and load?

This is deliberately a sequence experiment. EXP-0221/EXP-0230 separately established that the
generated `device_store` data descriptor can read r0..r95 and that generated `device_load` can
materialize r0..r95. Inferring a usable transfer primitive by composing two independent results
would skip memory visibility, in-flight-result, and register-release behavior.

## Frozen hypotheses

For source codeword `V`, destination poison `P`, and the bound scratch word's initial value `M`:

- **H-exact (primary):** scratch becomes V and destination becomes V.
- **H-stale-destination:** scratch becomes V but the destination remains P.
- **H-zero:** scratch and destination read zero.
- **H-source-mod64:** the store reads `r(source mod 64)` instead of an upper source.
- **H-store-absent:** scratch remains M and the load returns M.
- **H-alias/fault:** a different register changes, or the sequence faults/hangs. Complete buffer
  state and explicit modulo-64 register witnesses record these outcomes without folding them into
  a passing model.

The exact model must be the unique model with zero mismatches across both formal runs. A clean
result at gap zero establishes the shortest tested sequence. A result only at a positive gap is
reported as a bounded observation, not as a general scheduling rule.

## Variables and coverage

- Sources: `{r0,r11,r16,r63,r64,r95}`.
- Destinations: `{r1,r10,r17,r62,r65,r94}`.
- Store-to-load gaps: `{0,1,4,16}` independent `mov_imm r13,...` instructions.
- Matrix: 6 × 6 × 4 = **144** main programs. It covers every low/mid/high direction at each gap
  and explicitly includes r0, r63/r64, and r94/r95 boundary representatives.
- Two negative controls: one predicts the wrong scratch word; one predicts the wrong loaded value.
- Target: Apple A18 Pro / G17P at `192.168.170.254`, compute stage, one thread.

The formal captures run the same case set in canonical and reverse order.

## Exact authored sequence

Each program seeds its source with `imem[900+S] = 0x5A17C0DE XOR (S*0x01010101)`, seeds the
destination with a distinct poison codeword, and independently seeds modulo-64 alias registers.
Every generated seed load is immediately materialized by the established load-forwarding store
path and observed before the body.

The body under test is exactly:

```text
device_store rS -> mem[3200]
0, 1, 4, or 16 independent mov_imm instructions
device_load  mem[3200] -> rD
```

The store uses index r14=4 and `idx_off=199`; its established address formula yields byte 3200.
The store releases r14. The load uses index r15=7 and `idx_off=793`; its independently established
address formula also yields byte 3200. The load must retain r15=7. These nonzero indices make both
lifecycle outcomes observable instead of letting release and retention alias at zero.

The load is followed by an established `addr_mode=LOADFWD` store of rD, which both consumes the
in-flight result and exposes its value. Later independent stores observe source retention,
destination persistence, both modulo-64 aliases, r14, r15, and the integrity sentinel. All three
bound buffers are compared byte-for-byte against the host oracle, including scratch guards and
stray writes.

## Five gates

- **A — geometry:** requested fields, generated bytes, bytes read back from the dispatched archive,
  independent decode, offsets, program hash, and body instruction count are recorded. Each main
  body must decode as one store, exactly the declared number of fillers, and one load.
- **B — detection:** pre-body source/destination witnesses and post-body sentinel must pass. The
  wrong-scratch and wrong-load controls must both fail the complete-state oracle.
- **C — semantics:** every successful case is scored against all five frozen models. Exact must be
  the unique zero-mismatch model in both runs; lifecycle witnesses must read r14=0 and r15=7.
- **D — generation:** every field is assembled from documented project rules. `COPIED=0` and
  `CARRIER=0` are mandatory. No compiler-emitted instruction bytes or required fields are used.
- **E — target/reproduction:** two quiet G17P runs in opposite order must agree on program hashes,
  actual-byte ledgers, complete observations, outcomes, and target state, with no foreign runner or
  unexplained recovery delta.

## Finite-resource and safety rules

This experiment tests the complete 3×3 register-tier direction matrix and both sides of the
r63/r64 boundary. It does not replace the already committed dense 96-GPR endpoint sweeps and must
not be cited as one. Any finite resource encountered by the sequence is recorded with its exact
used value; no behavior above a bound is inferred from acceptance below it.

Every dispatch has a 20-second watchdog and raw JSONL is append-only and line-flushed. If the
device becomes unresponsive, immediately stop, preserve the last record, perform no recovery or
reboot, and report the goal blocked.
