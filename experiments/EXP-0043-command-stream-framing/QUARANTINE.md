# Quarantined generic analysis — excluded from evidence

During the post-capture audit, the first-generation `analyze.py` and
`framing_summary.py` were found to enumerate and mechanically scan every BO in a
capture directory. Some captures contain unclassified runtime auxiliary program
bytes. Even though the scripts looked only for numeric command/pointer patterns
and never disassembled code, enumerating all payload bytes violates this
experiment's stricter rule to inspect only pre-classified command/state/
descriptor data.

The response is conservative:

- raw IOKit logs and BO/map snapshots remain valid immutable DATA-TRACE evidence;
- all reports produced by directory-wide payload scans are retained under paths
  containing `quarantine` for auditability, but are excluded from conclusions;
- the unsafe generic scripts are retained only under `quarantine/` and are not
  reproduction entry points;
- clean reports are regenerated by `safe_framing.py`, `safe_fields.py`, and
  `safe_compare.py`, which accept explicit snapshot files and never enumerate a
  capture directory or dereference an encoded address;
- `manifest.json` excludes quarantined paths, and
  `verify_clean_evidence.py` proves the evidence allowlist contains no
  quarantined or generic-derived artifact.

No observation in `RESULTS.md` may cite a quarantined artifact. If a clean
explicit-file analysis cannot reproduce a claim, the claim must be removed.
